# UnB computers

Одностраничный сайт UnB computers с актуальным Excel-прайсом и закрытым
управлением через Telegram-бота.

## Как это устроено

- Главная страница и все кнопки скачивания используют `/api/price/download`.
- Telegram webhook принимает документы `.xls` и `.xlsx` только от подключённых рабочих чатов.
- Перед публикацией бот показывает имя и размер файла и просит подтверждение.
- В обычном облачном режиме Telegram бот получает напрямую файлы до 20 МБ, а для больших файлов оставляет защищённую браузерную загрузку.
- В режиме официального Telegram Local Bot API файл XLS/XLSX до 1 ГБ отправляется прямо в чат с любого устройства. После подтверждения локальный gateway читает файл из Telegram и передаёт его в R2 частями по 8 МБ; ссылка на localhost не нужна.
- Формат, структура Excel-файла и фактический размер проверяются на сервере до публикации. Зашифрованные и содержащие макросы legacy XLS отклоняются.
- Файлы версий сохраняются в R2, текущая версия и история — в D1.
- `/api/price/meta` обновляет дату и номер версии на странице без новой сборки сайта.
- При публикации XLSX проверяются зелёные заливки строк товаров. Названия найденных
  новинок сохраняются вместе с версией прайса и выводятся отдельным блоком «Новинки»
  на сайте; цены, артикулы и другие поля в этот блок не попадают.
- `public/price.xlsx` используется как безопасный резервный файл.

Подробная пользовательская инструкция находится в `OWNER_GUIDE.md`.

## Публикация

Репозиторий хранит полный исходный код. Публичный интерфейс публикуется через
GitHub Pages из корня ветки `main`; статические ресурсы лежат в `docs`, а серверные
API-маршруты, D1, R2 и секреты Telegram работают в Cloudflare Workers/Sites.
Pages получает актуальную дату и ссылку на прайс из публичного API.

Токены и production-секреты нельзя добавлять в Git: используйте секреты
выбранного хостинга. Локальные значения хранятся только в игнорируемом
`.dev.vars`.

## Локальная разработка

Требуется Node.js `>=22.13.0`.

```bash
npm install
npm run dev
npm run build
npm run typecheck
npm test
```

Для локальных ответов Telegram заполните игнорируемый файл `.dev.vars` по
образцу `.dev.vars.example`, запустите сайт, а затем отдельным процессом:

```bash
npm run bot:dev
```

### Прямая загрузка больших файлов из Telegram

Облачный Bot API не позволяет боту скачать файл больше 20 МБ. Для прямого
сценария используется официальный `telegram-bot-api --local`, который должен
работать на том же компьютере, что и `npm run bot:dev`.

Первое переключение выполняется в таком порядке:

1. Остановите запущенные `npm run bot:dev`, `npm run bot:api` и `npm run dev`.
   Одновременно должен работать только один polling-процесс этого бота.
2. Получите отдельные `api_id` и `api_hash` в `API development tools` на
   `my.telegram.org`. Заполните `.dev.vars`: `TELEGRAM_API_ID`,
   `TELEGRAM_API_HASH`, длинный случайный `TELEGRAM_LOCAL_BRIDGE_SECRET` и строго
   `TELEGRAM_API_BASE_URL=http://127.0.0.1:8081`. Собранный официальный
   `telegram-bot-api` v10.2 для arm64 уже ожидается по адресу
   `.telegram-bot-api/bin/telegram-bot-api`; launcher использует его по
   умолчанию. Каталог данных по умолчанию — игнорируемый
   `.telegram-bot-api/data`. Если задаёте `TELEGRAM_LOCAL_FILES_ROOT` вручную,
   используйте абсолютный путь; другой бинарный файл можно указать абсолютным
   или относительным от корня проекта путём в `TELEGRAM_LOCAL_API_BINARY`.
3. Пока сайт остановлен, примените локальные миграции D1:

   ```bash
   npm run db:migrate:local
   ```

   Команда использует `wrangler.local.jsonc`, каталог состояния
   `.wrangler/state` и штатный журнал Wrangler для файлов из `drizzle` — ту же
   локальную D1, с которой запускается сайт. На чистой базе применится весь
   набор `0000–0005`; при повторном запуске выполняются только новые миграции.
4. В первом терминале запустите Local Bot API и дождитесь, пока он начнёт
   принимать соединения:

   ```bash
   npm run bot:api
   ```

5. Во втором терминале ровно один раз отключите этого бота от облачного Bot API:

   ```bash
   npm run bot:cloud-logout
   ```

   Скрипт берёт токен только из `.dev.vars`, не передаёт его в аргументах и не
   выводит в терминал. Он откажется работать, если локальный адрес не равен
   `http://127.0.0.1:<порт>` или Local Bot API ещё не принимает соединения.
6. В третьем терминале заново запустите сайт, чтобы он перечитал `.dev.vars`:

   ```bash
   npm run dev
   ```

7. В четвёртом терминале запустите polling:

   ```bash
   npm run bot:dev
   ```

При обычном перезапуске повторяйте только шаги 4, 6 и 7; `logOut` повторно не
нужен. Polling до двух минут ждёт готовности Local Bot API. Длинная передача
файла идёт в фоновой очереди, поэтому команды бота продолжают обрабатываться;
`Ctrl+C` безопасно отменяет активную передачу, после чего её можно запустить
кнопкой «Повторить».

`logOut` — отдельный осознанный шаг: после него Telegram не разрешает вернуть
бота на облачный Bot API в течение 10 минут. Local Bot API слушает только
`127.0.0.1` и не публикуется в интернет.

Polling удаляет webhook только если его нет или явно задано
`LOCAL_BOT_TAKEOVER=1`. Остановленный локальный процесс webhook автоматически не
восстанавливает; перед production его нужно настроить заново. Для разработки
безопаснее использовать отдельного тестового бота.

После изменения `db/schema.ts` создайте миграцию:

```bash
npm run db:generate
```

Cloudflare runtime-типы сохранены в `worker-configuration.d.ts`. После изменения
bindings их нужно обновить через Wrangler и оставить `mainModule` направленным на
`./worker/index`, чтобы проверка типов работала и до первой сборки.

## Переменные окружения

Образец находится в `.env.example`. В production токен бота, секрет webhook и
код первого подключения должны храниться как секреты хостинга, а не в Git.
